HOW DOES A BINARY TREE WORK?

A binary tree is made of nodes, and each node has at most two children: a left child and a right child. This page uses a binary search tree, where smaller keys go to the left of a node and larger keys go to the right. Because of that rule, searching can skip half of the remaining tree at every step.

Methods Used

  • search(root, key): Walk down from the root, going left or right, until the key is found or the path ends.
  • post_traversal(start, traversal): Visit the left subtree, then the right subtree, then the node itself (Left, Right, Root).
  • delete_node(root, key): Remove a key and return the new root of that subtree, keeping the search-tree rule true.

THREE CASES OF DELETING A NODE

  1. Leaf (no children): simply remove it.
  2. One child: replace the node with its only child.
  3. Two children: copy the in-order successor's key into the node, then delete the successor from the right subtree.

With the sample tree, post-order gives 20, 40, 30, 60, 80, 70, 50: every node is visited only after both of its children.
